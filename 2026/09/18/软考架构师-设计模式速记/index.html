设计模式速记：创五结七行十一

发表于2026-09-18|更新于2026-09-18|系统架构设计师
|浏览量:

架构师上午题里，设计模式几乎年年有。考法就两类：

  1. 给场景，选是哪种模式
  2. 给类图 / 英文名，判断模式或填空

先把数字钉死：

GoF 23 种 = 创建 5 + 结构 7 + 行为 11
口诀：创五结七行十一

大类 数量 一句话
创建型 5 怎么造对象
结构型 7 怎么拼结构
行为型 11 怎么协作

注意：简单工厂不是 GoF 23 种之一，但真题常和工厂方法一起考。

创建型 5 种：单原工建抽

口诀：单原工建抽（单例、原型、工厂方法、建造者、抽象工厂）

模式 英文 一眼辨认 使用场景
单例 Singleton 全局只允许 1 个实例 配置中心、线程池、日志管理器
原型 Prototype 克隆已有对象，而不是 new 对象创建成本高，或要保留当前状态再复制
工厂方法 Factory Method 子类决定造哪一种产品 产品类型会扩展，不想改客户端代码
建造者 Builder 分步组装复杂对象，同一流程不同表示 生成复杂对象（报表、SQL、套餐），步骤固定、结果可变
抽象工厂 Abstract Factory 造一族相关产品（产品族） 整套 UI 风格 / 数据库驱动族要一起切换

工厂方法 vs 抽象工厂（必考）：

题干出现「一系列相关对象」「产品族」，选 抽象工厂。
出现「把实例化推迟到子类」，选 工厂方法。

结构型 7 种：适桥组装外享代

口诀：适桥组装外享代

模式 英文 一眼辨认 使用场景
适配器 Adapter 接口不通，硬转成能用的 接入老系统、第三方库，接口对不上
桥接 Bridge 抽象和实现分开，各自独立变 消息发送（短信/邮件）与发送时机（实时/定时）独立扩展
组合 Composite 树形结构，整体和部分一样用 文件夹树、组织架构、菜单权限，统一增删查
装饰 Decorator 动态加功能，像套娃 给输入流加缓冲、加密、压缩，运行时自由叠加
外观 Facade 给复杂子系统一个统一大门 启动流程封装多个子模块，客户端只调一个接口
享元 Flyweight 共享细粒度对象，省内存 大量重复字符/图标/棋子，只存一份内在状态
代理 Proxy 控制访问，代别人干活 远程调用、懒加载、权限校验、缓存代理

适配器 vs 桥接 vs 装饰 vs 代理（必考四兄弟）：

模式 核心词
适配器 兼容旧接口
桥接 维度拆分（抽象 / 实现）
装饰 增强功能，可叠多层
代理 代理控制（权限、延迟、远程）

行为型 11 种：责命解迭中备观状策模访

口诀：责命解迭中备观状策模访

模式 英文 一眼辨认 使用场景
责任链 Chain of Responsibility 请求沿链传，谁有能力谁处理 多级审批、异常处理链、过滤器链
命令 Command 把请求封装成对象，可排队、撤销 撤销/重做、任务队列、宏命令、事务日志
解释器 Interpreter 定义文法并解释句子 简单规则引擎、表达式求值、SQL/正则解析
迭代器 Iterator 顺序遍历集合，不暴露内部 统一遍历数组、链表、树，不关心底层结构
中介者 Mediator 多方不直连，都找中介说话 聊天室、机场调度、多个控件通过中介通信
备忘录 Memento 存档对象状态，以后能恢复 编辑器撤销、游戏存档、配置回滚
观察者 Observer 一对多，状态变了自动通知 发布订阅、事件总线、模型-视图解耦
状态 State 状态变了，行为跟着变 订单/工单/电梯状态机，每种状态行为不同
策略 Strategy 算法族可互换，消灭 if-else 支付渠道、排序/压缩/路由算法可切换
模板方法 Template Method 骨架固定，步骤子类填 固定流程（导入导出、JUnit 测试），细节子类实现
访问者 Visitor 数据结构稳定，操作经常变 对 AST/文档对象树做统计、检查、格式化等多种操作

高频场景：题干关键词 → 模式

题干关键词 选
全局唯一 / 只有一个实例 单例
克隆 / 复制已有对象 原型
分步构建 / 同一建造过程不同结果 建造者
一族相关产品 抽象工厂
旧接口和新接口不兼容 适配器
抽象与实现独立变化 桥接
文件树 / 菜单树，叶子和文件夹统一操作 组合
运行时动态叠加功能 装饰
子系统太多，客户端只想调一个入口 外观
大量相同小对象要省内存 享元
远程代理、权限控制、延迟加载 代理
请求排队、撤销、重做 命令
发布订阅、事件通知 观察者
支付方式 / 排序算法可切换 策略
订单状态：待付→已付→发货，行为不同 状态
算法流程固定，某些步骤子类实现 模板方法
多级审批，一级一级往下传 责任链
对 AST / 表达式树做多种遍历操作 访问者

三组最爱混

1. 策略 vs 状态 vs 模板方法

2. 观察者 vs 中介者

3. 装饰 vs 代理

和架构原则怎么挂

设计模式不是背名字，是落实原则：

原则 常对应模式
开闭原则 策略、装饰、工厂方法
依赖倒置 抽象工厂、桥接
合成复用 装饰、组合
单一职责 外观、中介者
里氏替换 所有基于多态的模式

考场 30 秒做题法

  1. 先判大类：造对象 / 拼结构 / 分工协作
  2. 抓题干里的动词：创建、转换、通知、封装、分步、撤销……
  3. 碰到工厂，先问是「一个产品」还是「一族产品」
  4. 碰到结构四兄弟，先问是兼容、拆分、增强还是控制
  5. 类图填空常考：Creator/Product（工厂）、Component/Decorator（装饰）、Subject/Observer（观察者）

收束

出门只背三串：

再加四句救命：

一族产品 → 抽象工厂
抽象实现分开 → 桥接
请求能撤销 → 命令
状态变了行为变 → 状态；算法随便换 → 策略

页式存储位图：先把小例子算懂
原题： 操作系统采用页式存储管理，用位图管理空闲页框。页大小 4KB，物理内存 16GB，位图占多少 KB？A. 64 B. 512 C. 256 D. 128 很多人直接套 2^34 / 2^12 / 8，数字一大就晕。下面不先甩公式，先把「位图在干什么」讲清楚，再用一个很小的内存算一遍，最后才回到这道题。 1. 这题到底在问什么物理内存被切成很多个大小相同的格子，每个格子叫 页框。 操作系统必须记住：哪个格子空着、哪个已经占用。本题用的办法是 位图：给每个格子配一个开关。 开关只有两种状态：占用 / 空闲 两种状态用 1 个二进制位（bit） 就够了 格子有多少个，位图就有多少个 bit 所以这题其实只问一件事： 16GB 的内存，按 4KB 一块来切，会切出多少块？每一块用 1 bit 记账，这些 bit 加起来占多少 KB？ 2. 页式存储：把内存切成固定大小的格子可以把物理内存想成一排储物柜。 每个柜子一样大，本题里每个柜子是 4KB 这样的一个柜子，操作系统叫它 页框 程序里同样大小的一块数据，叫 页 程序要运行时，某个页会被放进某个空闲页框里...
