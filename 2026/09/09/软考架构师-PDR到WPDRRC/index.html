从 PDR 到 WPDRRC：每多一个字母多一层

发表于2026-09-09|更新于2026-09-09|系统架构设计师
|浏览量:

软考把这几个动态防御模型放在一起考，本质上只问一件事：

后面的模型，比前面的模型 多了哪几个字？

别把字母表背成单词表。先记住骨架 PDR，后面全是在它身上加能力。

先抓住骨架：PDR

PDR 是后面所有模型的底板，三个字：

字母 中文 在干什么 常见手段
P 保护 Protection 先把门关上 防火墙、加密、认证、访问控制、杀毒
D 检测 Detection 看看有没有人进来 入侵检测、漏洞扫描
R 响应 Response 发现了立刻处置 阻断、隔离、应急响应

它相对「只堆防火墙」的静态防护，强调：防不住也要能发现、能处理。提出方常考：美国 ISS 公司。

PDR 还有一个几乎必考的时间关系：

  • Pt：保护撑住的时间（攻击者攻破防护要花多久）
  • Dt：检测出攻击要花多久
  • Rt：响应处置要花多久

人话就是：

门锁能扛的时间，必须长过「发现入侵 + 把人赶走」。

扛得住，系统就算安全；扛不住，检测和响应再快也来不及。

加「策略」：PPDR / P2DR

PPDR 就是 PDR 前面多一个 Policy（策略）。试卷里写成 PPDR 或 P2DR，是同一个东西。

策略是核心：保护怎么做、检测查什么、响应按哪套流程，都听策略的。
没有策略，三个环节各干各的，形不成闭环。

选择题里出现「以策略为核心的动态安全模型」，优先选 PPDR / P2DR。

加「恢复」：PDRR

PDRR 是 PDR 后面多一个 Recovery（恢复）。常考出处：美国国防部。

多出来的「恢复」管的是：打完了怎么把业务拉起来。备份、容灾、业务连续性，都落在这一层。

教材里常把它说成 四道防线：

  1. 保护：尽量进不来
  2. 检测：进来了能看见
  3. 响应：看见了能顶住（打不垮）
  4. 恢复：顶不住也能尽快起死回生

和 PPDR 别混：

  • PPDR 多的是 策略（谁说了算）
  • PDRR 多的是 恢复（打完怎么活）

再加「管理」：MPDRR

MPDRR 是在 PDRR 前面再加 Management（管理）。

技术手段之外，把人员、制度、流程抬进来。可以记：PDRR 解决「事」，M 解决「谁来管这些事」。

中国模型：WPDRRC

WPDRRC 是我国在 PDR / PPDR / PDRR 基础上提出的动态模型。相对 PDRR，一头一尾各加一截：

  • 头上加 W 预警 Warning：还没打进来，先有迹象
  • 尾上加 C 反击 Counterattack：处置完还要追溯、反制

六个环节按时间走：事前预警 → 事中保护/检测/响应 → 事后恢复/反击。

它还强调 三大要素，这组搭配经常单独出题：

人员是核心，策略是桥梁，技术是保证。

一张对照表（考场对号入座）

模型 比 PDR 多了什么 一句话
PDR 无 保、检、响，动态闭环
PPDR / P2DR 策略 策略当家
PDRR 恢复 四道防线，能起死回生
MPDRR 管理 + 恢复 有人管的 PDRR
WPDRRC 预警 + 恢复 + 反击 我国模型，全生命周期

默写口诀：

选择题常见挖坑

  1. PPDR 和 PDRR 互换
    看到「策略是核心」选 PPDR；看到「恢复 / 四道防线 / 业务连续性」选 PDRR。

  2. PDRR 的四道防线顺序
    保护 → 检测 → 响应 → 恢复。防火墙属于第一道（保护），备份恢复属于第四道。

  3. 时间公式张冠李戴
    Pt > Dt + Rt 是 PDR 的。不要安到 WPDRRC 头上当六个环节的公式。

  4. WPDRRC 三大要素说反
    人员是核心，不是技术是核心。

  5. P2DR 当成另一个模型
    P2DR = PPDR，两个 P 一个是 Policy，一个是 Protection。

收束

这组知识点不是五个彼此无关的缩写，而是一条加长链：

先有 PDR 三环节和 Pt > Dt + Rt；
加策略变成 PPDR，加恢复变成 PDRR，再加管理变成 MPDRR；
我国再加预警和反击，变成 WPDRRC，外加「人员、策略、技术」。

把「多了哪个字母」看清，这题基本就不会丢。
